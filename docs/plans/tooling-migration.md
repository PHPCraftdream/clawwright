## Policy leaf and transitional boundary

`tools/tooling-policy` audits the committed/index snapshot, not working-tree bytes: `git ls-files --full-name --stage -z -- tools/` supplies repository-root-relative paths, modes and blob IDs, and `git cat-file blob` supplies the exact audited content. The checker resolves any supplied existing directory (including a linked worktree subdirectory) to its actual Git worktree top-level before inventory; a path outside a worktree fails clearly instead of producing an empty success. The baseline is the immutable commit `8eadbd4e8dcfac3d6e11fe5ee49525da5baa3482`.

Every tracked `tools/` path is classified. Go, TypeScript/JavaScript, C/C++, Python, Rust, shell and PowerShell are implementations and count toward a 700-physical-line ceiling. Non-Go implementations retain their baseline blob identity except for four exact Rust fallback paths: `tools/native/task240-launch-stub/main.rs`, `linux.rs`, and `packet.rs`, plus `tools/native/task245-domain-init/main.rs`. These are narrow fallbacks for a single-task kernel/pre-exec boundary and raw-fork mount/ID lifecycle; they do not establish Rust preference or blanket language allowance. There is no Cargo dependency or C shim source authorized. Rust files remain subject to 700 lines; directories to at most 7 immediate entries. The baseline remains immutable.

The exact finite `tools/native/task245-acceptance/run.py` baseline transformation for the two Rust build entries is pending CI: policy source contains a single-anchor replacement of the exact baseline C build-list fragment with the Rust `rustc` build block, and admits only the resulting exact blob. Do not describe the runner as frozen or the transition as verified. No broad Python exemption is allowed. Classification is extension-based, not content parsing; data may carry declarative executable behavior. Directory limits count tracked files and derived directories, excluding untracked, ignored, generated and empty directories. The checker audits the Git index, not unstaged working-tree changes.

The ceiling is a fixed baseline ceiling, not a historical ratchet: after a file is reduced, it may later grow back up to its original baseline without explicit tightening. Existing grandfathered debt is reported, not completion. Immediate-entry limits prohibit new children while a directory remains over limit. Inventory and debt are report output, separate from violations.

## Credible migration order

1. First migrate narrow release checks with concrete callers: `tools/checks/release/license-audit.ts` and `license-audit.check.ts`, invoked by `npm run license:audit`; verify parity before changing that caller.
2. Next migrate named `docs/dev` checks, then installer/package checks such as `tools/checks/foundation/packaging/build-output.check.ts`, then runtime checks. Keep each existing npm/workflow caller and compare fixtures before switching it.
3. Keep this standard-library checker and its parsing, classification, ceiling and ratchet tests self-contained; do not treat this as general Rust permission.
4. Treat native admission/provider, policy, content, broker, supervisor and composed-lab as distinct runtime components with named tests/workflows as gates. Keep `stub.c` and `init.c` as parent-reviewed references until removal is reviewed; neither superseded stub/init file is compiled. The Rust fallbacks are narrow exceptions, not general tooling permission. Task #245 remains unaccepted; latest acceptance matrix `41335351818` failed with child exit **255** (not issue #255): broker receive timed out after 5 seconds and propagated to EOF. The monitor's `EAGAIN` fatal path is a separate, unfixed finding; other leaf work remains pending. No adoption claim follows.
5. The approved product boundary is to relocate the shipped TypeScript runtime/public library out of `tools/`, preserving its language, runtime behavior, generated JavaScript/declarations and public API. Do not rewrite that application/library runtime in Go. Update real build/import/package callers coherently and verify compatibility before removing old paths. Migration remains unfinished.

## Verification

`.github/workflows/tooling-policy.yml` runs on push, pull request and manual dispatch with Go `1.26.0`, disabled CGO, a ten-minute timeout, Bash strict mode and checkout credentials disabled. CI runs `go test ./...` and `go run . --root ../..`. `.github/workflows/native-supervisor.yml` records installed Rust toolchain/compiler versions (without an invented compiler pin), builds/tests both Rust components with `rustc --edition=2021 --target=x86_64-unknown-linux-gnu -C opt-level=2 -C panic=abort -C target-feature=+crt-static`, compiles the remaining out-of-scope C components, not the superseded stub/init. The authored test harness uses panic unwinding; `-C panic=abort` applies only to shipped builds. The authored launch stub has a single-thread gate: `GOMAXPROCS` controls runtime parallelism but does not make Go execution single-threaded, so this component cannot satisfy a true single-thread boundary as a Go implementation. The domain-init raw-fork/post-fork lifecycle is not a Go-runtime boundary. Current authored tests add positive parent-death cases, fresh namespace IDs, sealed-FD binding, and FD-refusal cases. Domain diagnostics report an exact numeric checkpoint and restore the most recent raw-syscall errno. Refusal captures the raw negative syscall result immediately; diagnostic output is a bounded raw write (at most 64 bytes and 64 attempts), not arbitrary logging. The authored public-kernel tests cover incremental field refusal and final EOF; these are authored tests, not evidence of execution or passing behavior. Miri cannot prove raw-kernel interactions or actual UB absence. No CI was run for this update.
