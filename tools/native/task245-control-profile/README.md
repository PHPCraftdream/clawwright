## Seccomp listener receiver ownership (source evidence)

The installer in `installer/linux.rs` sends the listener on FD 3 and closes its original listener; the metadata service receives one FD into local ownership without duplicating it, and calls `svc.loop` once. The authorized client does not receive the listener. This establishes the authored single-receiver ownership invariant for this flow; it is not a guarantee that arbitrary concurrent receivers are safe.

Linux v6.8 [`kernel/seccomp.c`](https://raw.githubusercontent.com/torvalds/linux/v6.8/kernel/seccomp.c): `recv_wait_event` consumes the atomic `requests` count before `seccomp_notify_recv` searches for an INIT notification. `seccomp_do_user_notification` removes an interrupted notification from the list without decrementing that count. Consequently, a later receive can consume a stale count and return `-ENOENT` when it finds no notification. `seccomp_notify_poll` checks notification states but does not reserve a notification for a receiver. This is the source basis for retrying `ENOENT` in the sole daemon receive loop, not evidence of a hang or of general multi-reader safety. The shown notifier ioctl path defines no `O_NONBLOCK` behavior.

Authored source includes a root-CI fixed canceled-notification mode: it pauses the sole daemon only after actual poll readiness, then the parent kills and reaps the filtered holder before releasing the daemon to receive. The daemon requires a real `ENOENT` counter and normal HUP success; the parent requires actual exit 0 and empty stderr before the outer timeout, with no ACK or socket involved. This describes authored assertions, not executed runtime evidence. The owning FIFO receipt tests and a short-service real-kernel refusal case are also authored; the latter expects EIO while the owner remains alive, no ACK, and daemon exit 0. Tests alone do not establish a 600-second guarantee. Kernel runtime/version validation remains outstanding; CI should record the actual kernel version (for example, from `uname -r`) when it runs.
