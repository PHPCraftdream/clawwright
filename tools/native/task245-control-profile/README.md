# Task 245 disposable-lab control profile

Linux/amd64 source prototype only; never installed or run in this session. It is not production-ready or evidence isolation works. A human-approved disposable Docker CI lab provisions a root-owned immutable `/lab/bin` bundle and read-only prepared root. No host sudo, host root provisioning, setuid helper, or production daemon is involved. Push CI only compiles/tests/builds; optional root-capability CI is manually dispatched and approval-controlled. Its C node is a protocol fixture, not OpenClaw identity or adoption.

The actual authored flow is ssjack CLI/launcher starting a same-process keeper child consumer, with sealed executable FD 3 and private input/output pipes. Root broker authenticates actual proc ancestry, executable hashes, FD identity/seals, pipe directions/custody and stable identities; caller claims are not authority. Consumer authenticates a request to the root broker. Broker verifies the whole prepared-root manifest read-only, actual Node/config and code identities, then launches fresh PID/mount/network namespaces (PID 1 init, PID 2 worker); worker drops to non-root UID/GID while host-root ownership is preserved. Hashes identify code/config, never grant authority. Keeper provides a finite per-write grant. Payload does not pass through root broker; provider performs OC-ADMIT/channel transfer and OC-PIPE-ACK, then SSACK.

Control profile applies Landlock and seccomp before execution, read/execute-only `/lab/bin`, and blocks `/proc`, AF_UNIX/SCM, and process-memory bypasses. The supervisor waits for actual gateway capture evidence before SSACK; OC-PIPE-ACK means provider write receipt, not gateway consumption. This source ordering has not been runtime-verified. No readiness/completion/adoption claim.

`metadata_test.c` includes the owning `metadata.c` implementation and directly tests `release_ack`: test-only wrappers invalidate the real ACK file descriptor to induce EBADF on write, fsync, and close. Each case asserts failure despite cleanup absence while the owner remains alive. The positive case observes and removes actual ACK content. Refused bad receipt, missing/wrong fault evidence, invalid payload, wrong owner parent, and pre-existing ACK content preservation are also asserted. This is source coverage only: the test is **NOT RUN** and does not exercise the complete seccomp-notifier path or substitute for keeper authorization. State snapshots and `owner_capture` are not covered by this owning test; the composed matrix remains unexecuted.
