=== clawwright help (installed) ===
==> clawwright — self-hosting framework for OpenClaw
    
    Usage: clawwright <command> [options]
    
    Start & stop:
      bootstrap            Bring the instance up (idempotent)
      up                   Start the service; wait until it serves
      restart              Restart so the instance re-reads its config
      down                 Stop and remove the containers (data is kept)
      destroy              Remove what bootstrap created *
      logs                 Follow the service log, or read a tail
      status               Show containers, image, health, data usage
    
    Check:
      smoke                Acceptance run: health, agent, config, snapshots, MCP
      inspect              Declared versus running, with differences
      doctor               Report what is wrong and what to run
      accept               Run this deployment's acceptance checks
      operations           What mutating runs did and left behind *
      watch                Health monitoring with webhook alerts *
    
    Change:
      upgrade              Update the image by digest; rollback on failure *
      plan                 Actions the declaration implies, without running
      apply                Apply the plan, then confirm the instance *
      rollback             Restore the configuration an operation replaced *
      apply-config         Apply the deployment's desired-state.json *
      deploy-text          Deploy a reference-only text template through SSJack
      memory               Declare, set up, inspect, index, verify memory *
      configure-provider   Configure model providers from target env vars
      secrets              Show required secrets and their state *
      recipe               Deploy service recipes beside the instance *
      files                Apply or preview declared deployment files *
      provision-agent      Wire a recipe's MCP server to an OpenClaw agent
      set                  Build or validate the set artifact *
    
    Save & move:
      backup               Snapshot data; list, prune, schedule *
      restore              Restore an archive over current state *
      pull                 Snapshot the instance to the snapshot directory
      push                 Push a snapshot onto the instance *
      verify               Check a snapshot for credentials
      lock                 Pin the instance's composition, or verify it
      deploy               Deploy over SSH and bootstrap the server *
    
    Security & access:
      expose               Expose the gateway: SSH tunnel or tailscale *
      incident             Contain, collect evidence, rotate tokens, audit *
    
    Integrations & recovery:
      recover-env          Repair .env from the running instance
      mcp-serve            stdio MCP bridge to the service's own channels
      mcp-setup            Configure project MCP servers (Claude Code, Codex)
      mcp-creds            Print service URL, token and MCP client config
    
    Low-level:
      cli                  Run the OpenClaw CLI in a throwaway container !
      exec                 Run a command in the same sidecar as `cli` !
      host                 Run a command on the host, not in a container !
      cli-start            Start the persistent CLI helper
      cli-stop             Stop the persistent CLI helper
    
    Framework:
      init                 Initialise this directory as an OpenClaw deployment
      version              Print clawwright's own version (also: --version, -v)
      completion           Print a shell completion script (bash, zsh or pwsh) to stdout
      control-mcp          Expose clawwright's commands as MCP tools, for agents
      help <command>       Same as: <command> --help
    
      ! destructive     * destructive for some actions (a read-only or --dry-run form is safe)
    
    Run `clawwright help <command>` or `clawwright <command> --help` for its full description.

=== clawwright init --help (installed) ===
==> init — Initialise this directory as an OpenClaw deployment
    Usage: clawwright init [--local]
      --local                Print the npm command for editor types (also in an already initialised directory)
    
    Writes app.ts, config/desired-state.json and .env (own data directory and project-specific port) directly into the current directory, plus config/, secrets/, recipes/, .gitignore entries for the deployment state and node_modules/, and a committed clawwright entrypoint that delegates to this package's CLI. Project MCP settings for Claude Code and Codex are created automatically, without changing global client settings.
    The port is randomized; it is not a host availability check. Bootstrap checks active Docker deployments on the target before preparing data or pulling an image.
    Refuses if app.ts already exists — run this once, then clawwright bootstrap. `init --local` in an already initialised directory only prints the editor-types npm line and writes nothing.

=== clawwright version --help (installed) ===
==> version — Print clawwright's own version (also: --version, -v)
    Usage: clawwright version [--json] [--verbose]
      --json                 Emit { name, version, source, path } instead of the one-line text
      --verbose              Also print which copy runs and where
    
    Reads the framework's package.json, as `inspect` does. No deployment is resolved, no .env is read, no lock is touched. --verbose / --json also say which copy runs: global, local (the app's own dependency) or checkout, and its path.

=== clawwright completion --help (installed) ===
==> completion — Print a shell completion script (bash, zsh or pwsh) to stdout
    Usage: clawwright completion <shell>
      <shell>                bash, zsh or pwsh [bash|zsh|pwsh] (required)
    
    Generated from the live command declarations — names, flags, and a multi-action command's own flags under the right action — so it cannot drift from --help.
    Install: eval "$(clawwright completion bash)"; clawwright completion zsh > "${fpath[1]}/_clawwright"; or take clawwright completion pwsh and pipe it through Out-String and Invoke-Expression.
    Completes the built-in commands only: a command a deployment declares itself is not offered, since the script is generated without loading any deployment.
    No deployment is resolved, no .env is read, no lock is touched.

=== clawwright status --help (installed, no app.ts here) ===
==> status — Show containers, image, health, data usage
    Usage: clawwright status [--json]
      --json                 Status as JSON
    
    Prints both health verdicts side by side — the HTTP probes (healthz/startupz/readyz) and the runtime's own opinion —
    because they can disagree: an image whose healthcheck binary is missing
    reports "unhealthy" forever while the gateway is serving traffic fine.
    --json emits the same facts structured instead of the container table, since that table is not machine-readable: target, runtime, exposure, bootstrapped, running, image, health, serviceUrl, dataUsage.
    
    "status" runs inside an app folder — there is no app.ts here; run: clawwright init
